# 作业 1：面向图像重建的 Objaverse 数据清洗

组号：第一组。成员代称：成员1、成员2、成员3、成员4；均衡分工安排见[正式报告](HOMEWORK2_REPORT.md)第1节与 `configs/submission.json`。源码和实际配置分别在 `programs/`、`configs/`，本报告描述本次已执行结果。

## 目标与范围

处理 `/mnt/aoss/datasets/Objaversev1.0/` 中 000-000～000-010（包含两端）的 11 个分片，共 55,000 个 GLB。筛出适合独立物体多视角匹配和新视角重建的资产，并从中选出 10 个对象用于作业 2。

Objaverse 提供几何、纹理、材质、类别和许可等信息。本项目将这些信息与实际渲染外观结合使用，避免仅凭标签或贴图数量判断重建适用性。[数据集论文](https://arxiv.org/abs/2212.08051)

## 筛选原则

1. 静态表面网格，无动画、点或线段；三角形列表、条带和扇形均可计为三角面。
2. 完整、独立、可识别的物体；排除建筑、房间、地形、场景、无关物体集合、残片和二维看板。属于同一物体的部件以及简单展示底座允许保留。
3. 表面具有可见纹理、图案、顶点颜色或明确的材质颜色变化。
4. 主体不透明、反光较弱；排除以玻璃、镜面或强反光金属为主的资产。
5. 面数为 500～1,000,000，文件大小不超过 100 MiB，能实际加载并渲染。
6. 根据文件 SHA-256 去除完全相同的内容。

材质判别以三角面数为权重。不合适材质超过 50% 时淘汰；贴图或顶点颜色至少覆盖 10%，或者有两种各覆盖至少 10%、RGB 距离不小于 0.2 的材质颜色。透明度、金属度、粗糙度等具体阈值在 `configs/glb_filter.json`。

## 实现与结果

| 阶段 | 方法 | 保留数量 |
|---|---|---:|
| 输入 | 11 个分片，各 5,000 个 | 55,000 |
| 元数据粗筛 | 无动画，面数与文件大小范围 | 44,597 |
| GLB 几何与材质 | 解析 GLB JSON、图元、颜色及材质覆盖比例 | 31,614 |
| 实际渲染 | Blender 导入和四视角渲染成功 | 31,607 |
| 前景与特征 | 前景面积和内部 SIFT 达标，进入视觉判别 | 17,150 |
| DeepSeek 与去重 | 综合外观判别，保留 UID 与 SHA | **7,819** |
| 作业 2 对象 | 从最终清单选择 10 个适用对象 | **10** |

最终保留输入的约 14.22%。保留模型之间完全重复的 SHA-256 数量为 0。

渲染先将包围盒中心移至原点、最长边缩放到 2，再在 (0°,20°)、(90°,30°)、(180°,20°)、(270°,30°) 四个方位/俯仰角取景。使用 Blender 4.5.3、Cycles CUDA、256×256、32 samples、GPU OIDN 去噪和 1024 像素纹理上限。每次导入前清理前一个资产的贴图与渲染缓存。

四视角以 alpha 提取前景。至少三个视角前景占比达到 2%，四视角前景内部 SIFT 数量中位数至少为 30，才调用 DeepSeek。灰度图先做 sigma=0.6 的平滑，掩码向内腐蚀 3 像素，降低轮廓和噪声产生的假特征。

DeepSeek 接收四视角 2×2 拼图，综合判断主体完整性、独立性、可辨识表面细节及材质。请求别名为 `deepseek-flash`，配置时版本记录为 `DeepSeek-V4.1-Flash-1017`；温度 0，关闭思考模式，JSON 返回 `keep` 与简短 `caption`，只根据 `keep=true` 保留。提示词原文见 `configs/preview_deepseek.json` 和 `docs/PROMPTS.md`。

正式运行记录 17,150 次请求。按当时配置的离峰费率估算为 $1.0621；同一用量按峰值费率估算为 $2.1242。这是同一用量的两种计费估算，记录范围为已提交批次。作业 2 实验不调用视觉 API。
