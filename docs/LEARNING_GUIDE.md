# 从清洗到重建：建议的学习顺序

这个项目把同一个物体依次表示为 GLB、多视角图像、相机与稀疏点、三维高斯，最后再渲染为新视角图像。先弄清楚每一步“输入是什么、输出是什么、依据什么优化”，再阅读参数，能更容易理解整个过程。

## 1. 先看一次完整结果

打开根目录 `index.html`，选一个物体，依次看输入图像、特征匹配、相机与点云、真实/预测/误差对照、重建 GIF。GIF 的每一帧来自训练后的高斯模型。原始 GLB 用于生成输入及参考图像。

建议先研究羊摆件，再比较罐头与机器人。它们分别具有雕刻纹理、印刷图案和旧化纹理，有助于理解表面特征与几何结构各自的作用。随后阅读 `docs/MATCHING_CASE.md`，观察重复纹理如何造成大量特征下的错误位姿。

## 2. 作业 1：为什么不能直接用所有 GLB？

源数据在 `/mnt/aoss/datasets/Objaversev1.0/`，本次处理 000-000～000-010 共 11 个分片、55,000 个模型。

“文件存在”并不代表“适合通过图像恢复相机”。一个模型可能是场景而非独立物体，可能缺少材质，也可能有大面积透明或光滑表面。因此按下面顺序筛选：

| 程序 | 输入 | 主要计算 | 输出 |
|---|---|---|---|
| `programs/coarse_filter.py` | 元数据 JSON.gz | 静态、面数、文件大小 | `outputs/coarse_candidates.jsonl` |
| `programs/filter_glb.py` | 粗筛清单和 GLB | 读取 GLB JSON，检查三角面类型、材质和颜色覆盖比例 | `outputs/material_candidates.jsonl` |
| `programs/render_candidates.py` | 材质候选 | Blender 导入，归一化，渲染四个视角 | `outputs/full_frames/` 与 `outputs/full_render/` |
| `programs/filter_previews_deepseek.py` | 四视角 RGBA | 前景面积、内部 SIFT、DeepSeek 综合判别、SHA 去重 | `cleaned/cleaned_models.jsonl` |
| `programs/finalize_cleaning.py` | 保留清单 | CSV、统计、预览和 10 物体选择 | `cleaned/` |

这里 SIFT 特征数量只是筛选线索；真正的对应关系要等同一物体的密集多视角图像生成后才能验证。四张清洗预览也不等于完整训练集。

DeepSeek 判断的是物体完整性、独立性、可见表面细节及材质表现。完整实际提示词在 `configs/preview_deepseek.json`。模型输出保留与否，不承担相机估计和三维重建。

最终 7,819 条清单引用原始文件路径，没有重新复制一套 GLB。SHA-256 去重针对完全相同的文件内容。

阅读时可以追踪一个 UID：在清洗清单找到它，再找到对应四视角预览，最后对应到 `configs/hw2_*.json`。

## 3. 作业 2：GLB 如何变成训练图像？

阅读 `programs/render_hw2.py` 与 `programs/prepare_hw2.py`。

已有 GLB 在这里作为可控的数据源：成像阶段用它生成照片和参考相机，后面的 SfM 与 3DGS 根据照片恢复表示。这样既能完成从图像重建的任务，也能用参考位姿研究相机误差。将来改成真实拍摄时，主要替换图像获取与标定步骤，后续匹配、重建和评价仍可沿用。

首先沿用清洗时的归一化矩阵：将物体包围盒中心移动至原点，最长边缩放到 2。然后固定物体与光照，移动相机。主实验在 -20°、15°、45° 三个俯仰角各拍 40 张，方位角间隔 9°。

每圈编号能被 5 整除的 8 张作为测试，其余 32 张作为训练，总计 96/24。划分在训练前确定，保存于 `data/splits.json`。

| 文件 | 用途 |
|---|---|
| `data/rgba/` | 保留原始透明背景渲染 |
| `data/images/` | 仅训练图，合成白色背景 |
| `data/test_images/` | 仅留出测试图 |
| `data/masks/` | 真实前景，用于前景指标 |
| `data/colmap_masks/` | 向内腐蚀后的训练前景，限制 SIFT 提取区域 |
| `data/metadata.json` | 内参、真实位姿、归一化和每帧角度 |

前景掩码可以避免把轮廓和背景当作物体表面特征。腐蚀半径为 3 像素。这里的掩码来自合成图 alpha；迁移到真实照片时，需要实际的前景分割方式。

## 4. 理解内参、外参和坐标变换

内参 K 描述三维相机坐标如何投影到像素：`u = fx * X/Z + cx`，`v = fy * Y/Z + cy`。外参 `w2c` 将世界点变到相机坐标，`c2w` 是它的逆。

Blender 相机局部坐标为 X 向右、Y 向上、朝 -Z 看；计算机视觉相机为 X 向右、Y 向下、朝 +Z 看。因此代码使用：

```text
c2w_cv = c2w_blender @ diag(1, -1, -1, 1)
w2c_cv = inverse(c2w_cv)
```

本实验相机经过标定：焦距 50 mm，传感器宽 36 mm，512 像素宽，对应 fx=fy≈711.11 像素，主点为 (256,256)。SfM 固定这些内参，从图像恢复外参和稀疏点。

如果只想训练一个已知相机的合成对象，可以直接使用这些标定位姿。这里保留 SfM 阶段，是为了完成从图像恢复相机的流程，并量化相机误差对最终结果的影响；真实训练位姿只在独立对照中替换使用。

SfM 结果存在整体旋转、平移和尺度的自由度。`align_centers` 仅用训练相机中心拟合一次 Sim(3)，并同时变换相机和点云，使它们进入渲染器的世界坐标。它保留各相机之间的估计误差；测试相机不参与拟合。

## 5. SIFT、匹配、几何验证和 SfM

阅读 `programs/reconstruct_hw2.py`。

1. **SIFT**：在图像上寻找稳定局部特征并计算描述子。
2. **匹配**：比较不同图像的描述子，寻找同一表面点的候选对应。这里使用穷举图像对、比例测试和双向一致性。
3. **几何验证**：用 RANSAC 排除不满足两视图几何的对应。匹配图显示几何验证后的内点，绘图最多展示 80 条线，标题保留实际总数。
4. **增量 SfM**：从可靠图像对开始，逐步加入相机和三角化点，再进行束调整，优化所有观测的重投影误差。

重投影误差是“三维点投影到图像的位置”与“观测特征位置”的像素距离。图像注册率表示多少输入图像成功估计了位姿。少量错误相机可能显著影响后面的高斯优化，所以应连同最终图像一起观察。

数据库 `sfm/database.db` 保存关键点、描述子、匹配和几何验证结果；`data/sparse/0/` 是训练实际使用的相机与稀疏点。`sfm/viewer.html` 可离线旋转点云并对照相机中心。

## 6. 3DGS 在训练什么？

阅读 `programs/train_hw2.py`，再进入 `.tools/gaussian-splatting/train.py`。

每个高斯具有中心、尺度、旋转、不透明度和球谐颜色系数。初始化使用 SfM 三角化点；随后可微渲染得到预测图像，与采样的训练视角比较，反向传播更新这些参数。

本实验使用官方默认的混合损失：`L = 0.8 * L1 + 0.2 * (1 - SSIM)`。训练早期还会增加、分裂和剪除高斯；15,000 步后停止增密，继续优化至 30,000 步。

一次迭代使用一个训练相机。一轮遍历 96 个相机后重新打乱。30,000 步约对应每张图参与 312～313 次优化，耗时随硬件、图像尺寸和高斯数量变化。

这里每个物体独立优化一个表示。增加其他物体的实验数量，可以检验流程适用性；不会自动使已有模型获得跨物体泛化能力。

`model/loss.csv` 是每 100 步记录一次的训练损失。`point_cloud/iteration_*/point_cloud.ply` 保存可渲染高斯；`chkpnt*.pth` 还保留继续训练所需的状态。高斯 PLY 的字段与普通带颜色点云不同。

训练损失描述模型对训练图像的拟合，判断新视角效果还要看留出图像。不同物体的前景面积、纹理频率不同，也不宜直接用训练损失高低给物体的重建质量排序。

## 7. 怎样判断效果？

阅读 `programs/evaluate_hw2.py`。

主实验评估固定的 24 张留出图像：PSNR 越高表示均方误差越小，SSIM 越接近 1 表示局部结构越相似。各视角先单独计算，再取算术平均。

白色背景占比较大，因此同时计算仅在真实前景 alpha>0.5 区域的 PSNR。前景指标与真实/预测/误差图结合看，更能发现物体纹理和轮廓的问题。

额外测试在 0°、30°、60° 高度，每圈 12 个视角，方位角偏移 4.5°。0°/30°检验不同高度间的插值，60°超出最高训练高度 45°，检验有限的外推。测试图像不会加入训练。

GIF 展示连续环绕时是否有漂浮点、轮廓抖动和纹理变化。新视角渲染质量与可用于制造的封闭三角网格是不同目标。

## 8. 从哪些实验开始优化？

先查看 `docs/EXPERIMENTS.md` 中的实际对照数据。建议一次改变一个条件：

| 想研究的问题 | 可修改的配置 | 应同时观察 |
|---|---|---|
| 视图数量够不够 | `experiment.train_stride` | 相机注册、稀疏点、前景 PSNR |
| 位姿误差是否关键 | SfM 与真实位姿对照 | 纹理清晰度、轮廓、前景 PSNR |
| 训练是否充分 | 7,000/30,000 步检查点 | 留出指标、训练耗时、高斯数量 |
| 高处是否缺少观测 | `render.elevations_degrees` | 新高度的误差图 |
| 纹理细节是否受分辨率限制 | `render.resolution` | 小字/细纹、显存与耗时 |

视图数量实验使用同一批图像的嵌套子集：24⊂48⊂96，测试图像完全一致。训练步数统一为 30,000；因此比较的是固定迭代预算下的最终效果。减少视图同时也改变每张图的使用次数，这是理解结果时应考虑的因素。

机器人 24 图条件还展示了相机恢复失败：只注册 19 个相机，几何明显退化。此时增加高斯训练步数不能替代正确的观测对应。表格区分输入图数与实际训练相机数，可结合稀疏点云、位姿误差和最终误差图追踪问题传播的过程。

真实位姿对照保持同一套 SfM 稀疏点初始化和训练设置，仅替换训练相机外参。它能帮助定位位姿的影响，但不应预设真实位姿对照必然在每个指标上都更好。

## 9. 复现和源码阅读路线

启动脚本均无参数，计算参数在 JSON 配置中。完成过的完整命令以 `#` 注释保留，取消对应行注释即可复现。Bash 调用实际程序，不调用其他 Bash 脚本。

第一次学习建议阅读顺序：

```text
configs/hw2_lamb.json
programs/render_hw2.py
programs/prepare_hw2.py
programs/reconstruct_hw2.py
programs/train_hw2.py
.tools/gaussian-splatting/train.py
programs/evaluate_hw2.py
programs/finalize_course.py
```

之后再回溯作业 1，理解为什么提前选出独立、低反光、表面细节充分的物体，可以降低后续匹配和重建难度。

参考：[Objaverse 论文](https://arxiv.org/abs/2212.08051)、[COLMAP 教程](https://colmap.github.io/tutorial.html)、[3DGS 原论文与实现](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)。
